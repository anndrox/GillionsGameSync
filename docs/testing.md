# Testing

This document describes the `1.0.30` source and its synthetic verification. The stable feed and GitHub Release identify the published package; separately installed testing builds retain their own identity and publication path.

Run `./scripts/verify.ps1` for the focused synthetic fixture executable, source contract checks, local packaging fixtures, stable/testing builds and actual Dalamud configuration round-trips. The configuration suite loads the built product's real configuration type with `PluginConfigurations.LoadForType`, invokes its normal Save wrapper through a storage-only test proxy, and serializes using Dalamud's own serializer. All fixtures are synthetic and stay under ignored `artifacts/verification`; no game session, user config, server or database is used. Both product identities cover populated backups, retired type metadata, unknown/malformed fields, scalar timestamp strings at both legacy roots, restored-but-unacknowledged ownership, missing legacy fields and repeated saves. Additional checks preserve ordinary typed dates/strings, ignored fields and root metadata behavior, prevent nested lookalike keys from receiving the root hook, and verify reader state and setting restoration on success/failure. A local build or package is not a release.

The updated plugin advertises only observation, result, exact-result-ACK and presence v1 capabilities. Neutral legacy AutoRetainer fields and empty applied-plan summaries retain old-server parsing compatibility without probing or controlling another plugin. Stable uploads require exact accepted product/contract identity; ordinary scopes remain available when Retainer support is absent or denied. Planner status in a server response cannot grant any executable client behavior.

Retained synthetic checks cover character switching, player opt-out, missing/partial/authoritative-empty observations, loaded and unloaded gear/inventory, listings, native roster/Gil/current venture/results, duplicate/revised result evidence, exact and failed acknowledgements, and presence expiry/backoff. Cached AutoRetainer stats/start times retain historical provenance and original observation timestamps. Fast result observation follows native task-view activity; no other plugin's loaded state or IPC is consulted.

Source and synthetic checks cannot establish game-version compatibility or universal cancellation of callbacks in older installed clients. Local verification does not claim in-game or visual acceptance. Required independent source/release reviews and explicit integration/publication authority remain distinct gates; the release record identifies which have passed. Existing external plans can continue independently of Gillions; no automatic restore or recovery subsystem is provided.
