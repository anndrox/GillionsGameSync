# Testing 0.0.88 — dedicated public experimental distribution

Testing keeps `GillionsGameSyncTest`, its own configuration, command
`/gillionssynctest` and existing read-only diagnostic capabilities. Source remains
the single GillionsGameSync repository; GillionsGameSync-Testing contains only
distribution documentation, a Dalamud feed and versioned release assets.
No second source fork, custom updater or Stable promotion exists.

The maintained dual-channel source includes published Testing87 in its ancestry.
Shared window sizing, repositioning, reconnect and Hunt-status implementations
come from frozen Public1.0.31.3 source43a8694. Testing adds only a channel notice.
It is a different assembly, version and conditional diagnostic UI—not the exact
frozen Public DLL or proof of its physical execution.

## Install, update and return

New custom repository:
`https://raw.githubusercontent.com/anndrox/GillionsGameSync-Testing/main/data/GillionsGameSyncTesting.json`

In Dalamud settings, add the custom repository, then find **Gillions Game Sync
Testing** in the plugin installer. This is a separate identity from Public.
Only one Game Sync copy may be enabled at a time: disable installed Public and
any dev copies before enabling Testing. Both may remain installed, but simultaneous
runtime operation is not supported (duplicate collection and shared Hunt-window
geometry are possible). Disabling does not reset configuration or pairing.

Existing Testing users disable/uninstall only the old Testing plugin without
reset/delete-configuration, remove only the old Testing feed, then install from
the new feed. Dalamud binds updates to the recorded installation URL, so changing
the URL alone is insufficient. Follow any normal installer reload prompt. Do not
remove Stable or erase configuration. Historical Testing87/old feed stay unchanged.
After this one-time source rebind, use normal updates through the new feed.

To return, disable Testing before enabling installed Public1.0.31.2. Remove the
Testing feed and optionally uninstall only Testing; Public's separate file and
pairing remain intact. Existing Testing histories/settings survive normal upgrades;
do not use reset/delete-config as an installation step. User-directed Testing
configuration deletion is separate from Public preservation.

## Offline and online boundaries

The public distribution is not public access to Gillions Site TEST. Unpaired
Testing can exercise local UI/Hunt Progress; no account is required for that.
Online testing requires network access to the existing secure TEST service,
a separately issued TEST pairing, account/character ownership and applicable
Site permissions. Most community users may not have that access. No credentials
are embedded or inherited from Public.

Testing's compiled default is exact HTTPS TEST. Every request family, including
ordinary startup hydration, pairing and item links, is fenced away from production;
HTTP redirects are disabled. Historical Testing production credentials/history
are preserved but inactive, not retargeted or copied into TEST. Public pairing
and transport behavior are unchanged. The existing explicit TEST setup controls
remain; no new destination selector or production enrollment is added.

FATE uses exact Site version/source admission. Current TEST accepts86/87, not88;
the packaged lifecycle remains fail-closed until separately authorized exact88
admission. This limitation does not prevent offline UI testing. Other online
features still require their own current acknowledgements/permissions. No production
Testing API admission is authorized or promised by this release.

## Owner physical checklist

1. Confirm Testing0.0.88.0 and no enabled Public/dev duplicate.
2. Stay unpaired/offline, or use only an existing supported TEST pairing. Do not
   re-pair Public or copy configuration. Confirm the TEST notice.
3. Open `/gillionssynctest`; resize/move Main and Settings, including the normal
   ultrawide position if applicable. Short windows scroll; close/reopen preserves
   geometry. Check normal mouse/keyboard/chat; no forced focus.
4. Inspect `pair` without submitting a code. A valid saved TEST connection has
   reconnect wording; an unpaired copy correctly has welcome wording.
5. Enable only local **Show Hunt Progress** if desired. Resize/lock it; confirm
   honest current-area/unknown messages. Missing rows never prove no bills or
   completion. Naturally observed progress may be checked; no manufactured kills.
6. Report version, a short support summary and cropped screenshots. Never post
   configuration, credentials, raw private exports or personal activity logs.
7. Disable Testing before returning to Public; retain Public pairing/settings.

Build, actual serializer, manifest/feed and source tests are synthetic/non-production
evidence. Fresh physical installation/update, corrected FFXIV placement/input and
gameplay-source acceptance remain owner validation; do not relabel fixtures as live.
Prior controller/live FC submarine limits remain. A successful shared-UI Testing
test does not automatically prove exact-Public-DLL execution; assess concrete
remaining differences before inventing another acceptance gate.
