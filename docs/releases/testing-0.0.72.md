# Testing 0.0.72 — Timers correction, Custom Delivery diagnostics and Doman

Corrects a source defect: valid global delivery allowances were suppressed by
early selected-client catalog/counter/rank failures. Global and client facts now
validate independently, after the same shared active visible UI, load and native
reset gates. Invalid/missing facts preserve retained history; no fabricated zero.
The private v1 field shape, capacity, opt-in and export rules are unchanged.

Corrects the Timers window name from `ContentsTimer` (the agent type) to
`ContentsInfo` (the UI addon), including lifecycle notices and source labels.
Requires the active owning AgentContentsTimer and matching visible window.
This restores the existing leve/society/map/squadron source group without new
resources, callbacks, requests, polling frequency or retained-field changes.

Adds a persistent **Custom Delivery read** line to `/gillionsfacts` and **Copy
aggregate facts diagnostics**. It contains only the latest finite gate reason
and attempt time, not player/NPC identifiers, counters or exception text. Other
source reads do not hide it; session/opt-out boundaries clear it. No extra polling,
game requests, automatic UI opening or upload. Stable and other Testing features
are unchanged.

Adds typed loaded-state Doman Enclave donated/allowance/remaining values and the
native accepting-donations flag, discovered through the GitHub reference audit.
No native reset timestamp is available, no weekly completion is inferred, and an
unloaded/zero-cap/incoherent manager preserves old state. Eight fair source groups
still read only one bounded group per five seconds (40 seconds normally, at most
80 with sustained UI notices). No hooks, requests or donation actions.

The owner reported no Custom Delivery rows after naturally opening Ameliance's
window for 70 seconds in 0.0.71. Existing diagnostics do not establish which gate
rejected it. This correction is not a claim that Ameliance live capture now works.
Primary assessed the complete correction and new Doman fields: same default-OFF
private activity consent, character partition, bounded persistence and deliberate
private export; no new identity, credential, public-sharing or trust authority.
Timers ownership is tightened. Prior independent privacy acceptance of those
unchanged boundaries carries forward; no new independent review is claimed.

## In-game check

Keep the existing Testing JSON URL and configuration. After updating, open
Ameliance's Custom Deliveries window manually and leave it visible up to 80
seconds. Copy aggregate facts diagnostics, including the new **Custom Delivery
read** line. If `ObservedBoth`, compare global used/12/remaining and selected
client count/rank with the game. If a rejection is shown, report that line; do not
share configuration, pairing secrets or private JSON. Do not make another
delivery merely to test exhausted allowances.

`ObservedGlobal` means only global counters passed. Other rejection reasons may
also preserve a valid global observation while client details remain unavailable.
Read status is not a claim that capacity-limited persistence accepted new rows.
Ownership/reset freshness remains unverified; no automated checklist completion.

Society facts are remaining allowances, spent on acceptance rather than turn-in.
Open Timers naturally to observe `society-allowance`; it does not report individual
completed society quests. After visiting the Doman Enclave donation interface
naturally, compare the new `doman-enclave-weekly` native counters if available;
this check is optional under the owner's reference-backed acceptance policy.

The [GitHub timer reference audit](../timer-plugin-references.md) identifies
typed Doman Enclave fields omitted from the earlier capability inventory.
The implementation now admits only the explicitly loaded, bounded native state;
its current-owner/server-reset freshness remains unverified. Owner-waived live
testing with source/SDK/fixture validation is not a live-success claim.

Site owns future authenticated intake and page integration. This release adds no
new server contract or upload path and does not modify Site or production.
